### 1. Удаление валидации суперблока
Из проекта исключена функция проверки суперблока (validate_superblock). Это означает:
- При открытии диска не проверяется:
  - Корректность «магического числа» (magic).
  - Соответствие заявленных параметров (например, block_count == MAX_BLOCKS).
- Файловая система не обнаруживает повреждение суперблока, что может привести к:
  - Использованию некорректных метаданных.
  - Ошибкам чтения/записи из-за неверных указателей на блоки.
  - Полной неработоспособности ФС, если суперблок был изменён.

### 2. Возможности файловой системы EduFS
#### Основные функции:
1. Создание и удаление файлов/каталогов:
   - Поддержка плоской и иерархической структуры (через каталоги).
   - Максимальный размер файла: 12 блоков * 4 КБ = 48 КБ.

2. Чтение и запись данных:
   - Побайтовая работа с файлами.
   - Контрольная сумма (CRC32) для проверки целостности данных.

3. Журналирование:
   - Логирование операций (создание, удаление, запись).
   - Возможность восстановления после сбоев (частичная реализация).

4. Управление свободным местом:
   - Битовая карта блоков для отслеживания занятых/свободных блоков.

5. Работа с каталогами:
   - Добавление и поиск файлов по имени.
   - Поддержка вложенных структур.

---

### 3. Достоинства EduFS
1. Простота:
   - Минималистичная кодовая база, понятная для изучения.
   - Отсутствие сложных структур (например, B-деревьев).

2. Надёжность базовых операций:
   - Журналирование критических операций снижает риск потери данных.
   - Контрольная сумма CRC32 для проверки целостности файлов.

3. Портативность:
   - Данные хранятся в файле-образе (disk.img), который можно переносить между системами.
   - Независимость от ОС (работает на Linux, Windows через эмуляцию).

4. Учебная направленность:
   - Понятная архитектура для изучения принципов работы ФС.
   - Реализация ключевых концепций: inode, битовая карта, журналирование.

---

### 4. Недостатки EduFS
1. Отсутствие валидации суперблока:
   - Повреждение суперблока сделает ФС неработоспособной без возможности восстановления.
   - Пример: Если поле inode_start будет перезаписано, система начнёт читать inode из случайных блоков.

2. Ограничения производительности:
   - Нет кэширования данных — каждое обращение к диску приводит к физической записи/чтению.
   - Линейный поиск свободных блоков и inode (сложность O(n)).

3. Нет поддержки больших файлов:
   - Максимальный размер файла — 48 КБ (12 блоков).
   - Нет косвенных или двойных косвенных блоков.

4. Упрощённое журналирование:
   - Нет механизма отката (rollback) для незавершённых транзакций.
   - Журнал хранится в одном блоке, что ограничивает количество записей.

5. Безопасность:
   - Нет разграничения прав доступа.
   - Нет шифрования данных.

### 5. Примеры сценариев использования
#### Учебные задачи:
- Изучение работы inode, битовых карт, журналирования.
- Эксперименты с восстановлением данных после сбоев.

#### Прототипирование:
- Быстрое тестирование идей для новых ФС без сложной реализации.

#### Специализированные задачи:
- Встраиваемые системы с минимальными требованиями к хранилищу.
- Локальное кэширование данных в приложениях.

### 6. Рекомендации по улучшению
1. Валидация структур:
   - Вернуть проверку суперблока и inode.
   - Добавить checksum для суперблока.

2. Расширение возможностей:
   - Поддержка больших файлов через косвенные блоки.
   - Реализация полного журналирования (например, как в ext3).

3. Оптимизация:
   - Кэширование часто используемых блоков.
   - Использование хеш-таблиц для быстрого поиска inode.

4. Безопасность:
   - Шифрование данных (AES-256).
   - Разграничение прав доступа (чтение/запись).

---

### Итог
EduFS — это учебная файловая система с базовой функциональностью, которая подходит для изучения принципов работы ФС, но не готова для промышленного использования. Удаление валидации суперблока снижает её надёжность, поэтому в реальных проектах такие проверки необходимы.
